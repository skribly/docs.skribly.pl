# Commity bez stopek AI

> Trzy niezależne warstwy, dzięki którym commity z agent-skills wyglądają jak Twoje — same skille, ustawienie atrybucji w Claude Code i hook commit-msg dla dowolnego narzędzia.

Commity mają wyglądać jak Twoje. agent-skills ma trzy niezależne warstwy, więc awaria jednej z nich nie szkodzi.

## 1. Skille

`commit` i `task` piszą wiadomości zgodne z konwencją projektu, wziętą z `.tasks/workflow.md` albo wykrytą z Twoich ostatnich commitów, i nigdy nie dodają stopek: ani `Co-Authored-By`, ani „Generated with”, ani linków do agentów czy podpisów z emoji. Robią commit dopiero po Twoim „ok”, do indeksu dodają tylko wymienione pliki i nigdy nie robią push, merge, rebase ani force, chyba że poprosisz o to w tej rozmowie.

## 2. Ustawienie Claude Code

```bash
agent-skills config attribution off                # ~/.claude/settings.json
agent-skills config attribution off --project .    # this project's .claude/settings.json
agent-skills config attribution status
agent-skills config attribution on                 # undo
```

Ustawia `"attribution": { "commit": "", "pr": "" }`, co ukrywa stopkę commita i stopkę pull requesta, oraz starsze `"includeCoAuthoredBy": false` dla wcześniejszych wersji Claude Code. Pozostałe klucze zostają, przed pierwszą zmianą powstaje kopia zapasowa, a niepoprawny JSON nigdy nie jest nadpisywany.

## 3. Hook gita, dla dowolnego narzędzia

```bash
cd ~/code/shop
agent-skills hooks install
agent-skills hooks status
agent-skills hooks uninstall
```

Hook `commit-msg` usuwa:

- stopki `Co-authored-by:`. Domyślnie wszystkie; aby zachować współautorów będących ludźmi, uruchom `git config agent-skills.keepHumanCoauthors true`, a usuwane będą tylko stopki AI.
- dopiski takie jak „Generated with Claude Code”, „Generated by GitHub Copilot” czy „Made with Cursor”. Wiersz „generated, made or created with” jest usuwany tylko wtedy, gdy wymienia narzędzie AI, więc „Generated with protoc” zostaje.

Nie dotyka niczego innego: temat, treść, `Signed-off-by`, wiersze komentarzy i wszystko poniżej linii scissors w `git commit -v` zostają bajt w bajt, razem ze znakami końca wiersza.

- Twój dotychczasowy hook `commit-msg` zostaje i nadal uruchamia się po tym hooku; odinstalowanie przywraca go.
- W repozytoriach korzystających z husky, lefthook lub innego `core.hooksPath` instalator nie przejmuje tego folderu. Wypisuje jeden wiersz, który trzeba dodać do własnego hooka: `node .git/hooks/agent-skills-commit-msg.cjs "$1"`.
- Hook wymaga `node` w `PATH`; bez niego sam się pomija, zamiast blokować commity.
- Hooki działają w obrębie jednego repozytorium i nie trafiają do commitów. Zainstaluj hook w każdym klonie.

Skribly Agent ma ten sam hook wbudowany: **Kod i git → Hook bez stopek AI**.

## Sprawdzanie starych commitów

```bash
git log --format='%h %s%n%b' | grep -inE 'co-authored-by|generated with' | head
```

Przepisywanie opublikowanej historii to decyzja zespołu; agent-skills nigdy tego nie robi.
