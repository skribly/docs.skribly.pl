# agent-skills

> 35 portable skills that take AI coding agents from a tracker ticket to a reviewed, tested commit - cheap on tokens, safe by default, with no AI co-author trailers.

**agent-skills** is a library of short, tested procedures (“skills”) for AI coding agents, plus a zero-dependency installer that puts them where each agent looks. It supports Claude Code, Codex CLI, Cursor, Gemini CLI, OpenCode, Windsurf, GitHub Copilot and Devin. Skills cover the whole loop: pick up a Redmine, Jira, GitHub, GitLab, Linear or Skribly Tracker issue, plan, branch, implement in stages, test, review, audit and commit. They also cover the specialist jobs around it: Core Web Vitals, load tests, safe migrations, Docker, CI, dependency upgrades, translations and release notes. A group of skills also covers the work around the code: writing a plan as work packages and running a work package task by task, decision records, a release checklist, the check that docs and translations move with a change, and the design review of a page. ![The skills catalogue in Skribly Agent: cards for each skill with its command, group and the agents it is installed for](/_astro/skills-catalog.DRGjq_KS_Z1i9TlW.webp) ## Principles [Section titled “Principles”](#principles) * **Scripts do the mechanical work.** Small Node scripts hand the model a few lines instead of megabytes: a 455 KB Lighthouse report becomes 754 bytes, a 27 KB test log 86 bytes. * **Every risky step waits for your OK.** Commits, comments on tracker issues, screenshots and long test runs are proposed, not done silently. * **Adapts to each project.** The `project` skill detects the stack, the commands and the commit conventions into `.skribly/project.json`, and every skill reads that profile first. Values you set by hand are never overwritten. * **Learns from the work.** At the end of `task`, `test-loop`, `review` and `debug` the agent proposes one confirmed lesson; with your OK, `learn` keeps it in `.skribly/lessons.md` for the next run. Lessons that look like secrets are refused. * **Commits look like yours.** Messages follow the project’s convention, and no skill adds a `Co-Authored-By` or “Generated with” trailer. * **Standalone.** It needs nothing else from Skribly and works in any repository. Skribly Agent is one optional place that uses it. ## Facts [Section titled “Facts”](#facts) | | | | -------------------- | ---------------------------------------------------------------------------------------- | | Version | 0.2.14 (11 November 2026) | | Skills | 35, in the shared [Agent Skills](https://agentskills.io/specification) format | | Agents | 8: Claude Code, Codex CLI, Cursor, Gemini CLI, OpenCode, Windsurf, GitHub Copilot, Devin | | Trackers | Redmine, Jira Cloud and Server/Data Center, GitHub, GitLab, Linear, Skribly Tracker | | Requirements | `git` and Node.js 20 or newer | | Runtime dependencies | None | | Licence | MIT | ## How a skill is built [Section titled “How a skill is built”](#how-a-skill-is-built) Every skill is a folder `skills/<name>/`: 
```text
skills/<name>/
  SKILL.md       at most 110 lines, read when the skill runs
  reference/     extra detail, read only when a step needs it
  scripts/       Node scripts with no dependencies that do the mechanical work
  templates/     files the skill fills in
```
 An agent keeps only each skill’s name and description in its context, one line per skill. The rest loads on demand. ## How it saves tokens [Section titled “How it saves tokens”](#how-it-saves-tokens) 1. **Load on demand.** `SKILL.md` loads when used, `reference/` only when a step needs it. The 110-line limit is enforced in CI. 2. **Scripts instead of the model.** Measured on real projects: | Task | Raw input | Script output | Saved | | --------------------------------------- | ------------- | ------------- | ----- | | Lighthouse report | 455,534 bytes | 754 bytes | 99.8% | | Test run log, 86 tests | 27,098 bytes | 86 bytes | 99.7% | | `npm audit --json` on a 300-package app | 20,555 bytes | 2,126 bytes | 90% | | `git log -60` to learn the commit style | 7,415 bytes | 739 bytes | 90% | | GitHub issue with comments | 8,178 bytes | 1,018 bytes | 88% | 3. **Ask before expensive steps.** Screenshots, Lighthouse runs and full suites need your OK. 4. **Restart instead of dragging transcripts.** `STATE.md` (about 30 lines) holds the goal, what was done and one next step, so you can `/clear` after each stage and resume, in the same or another agent. 5. **Working rules.** The `token-saver` skill gives every agent the same habits: search before reading, read line ranges, never open lock files or build output. The full measurements are on [Token saving](/agent/token-saving/). ## Read next [Section titled “Read next”](#read-next) * [Install](/skills/install/): user scope or project scope, updates, Windows. * [Skills catalog](/skills/catalog/): every skill and when to use it. * [Supported agents](/skills/agents/): where each agent gets the skills, and the files `agent-skills agent-files` generates from `AGENTS.md`. * [Trackers](/skills/trackers/): credentials for each tracker. * [Commits without AI trailers](/skills/commits/): the three layers that keep commits yours.

With Claude and one of those in the same project, a skill may show twice. Skills linked at user scope are activated through `activate_skill`, which grants access to the skill folder. ## Project instruction files [Section titled “Project instruction files”](#project-instruction-files) A repository keeps its instructions for coding agents in one file, `AGENTS.md`. Codex, OpenCode and Devin read it themselves. Claude Code, Gemini CLI, Cursor and Copilot need a small file of their own, and `agent-skills agent-files` generates those files from `AGENTS.md`, so you never write them by hand: 
```bash
cd ~/code/shop                      # a repository with an AGENTS.md
agent-skills agent-files            # write what is missing or out of date
agent-skills agent-files --check    # write nothing, exit 1 when a generated file is missing or differs
agent-skills doctor                 # each agent: configured or not for this repository
```
 Run it again after a `git pull` of agent-skills (new skill versions) or after a change to the structure of `AGENTS.md`. The pointer files contain no instructions, so editing `AGENTS.md` itself needs no re-run. The generator covers seven agents: Claude Code, Codex CLI, Cursor, Gemini CLI, OpenCode, GitHub Copilot and Devin. Windsurf reads `.agents/skills` and `AGENTS.md` too, so a generated repository works there without an extra file. | File | For | Contents | | --------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------- | | `CLAUDE.md` | Claude Code | A marker comment, then the one line `@AGENTS.md` | | `GEMINI.md` | Gemini CLI | A marker comment, then `@./AGENTS.md` | | `.cursor/rules/agents.mdc` | Cursor | An always-applied rule that references `@AGENTS.md` | | `.github/copilot-instructions.md` | GitHub Copilot | A marker comment and a link to `../AGENTS.md` | | `.claude/skills/<name>/` | Claude Code | The skills, copied | | `.agents/skills/<name>/` | Codex, Cursor, Gemini CLI, OpenCode, Copilot, Devin (and Windsurf) | The same skills, once for all | | `.mcp.json` | Claude Code | `{ "mcpServers": {} }`: read-only defaults and an empty server list | | `.skribly/agent-files.json` | The command | What was generated; commit it with the other files | Every text file starts with a comment that says it was generated by `agent-skills agent-files`. Claude Code strips that comment before it reads `CLAUDE.md`, so the agent still sees the single import line. `.mcp.json` never contains a token or a URL with credentials; servers are added by a person. The command is safe to run again and again: * **Twice is the same.** A second run changes nothing and prints `0 change(s)`; line endings do not matter. * **Hand-written files are kept.** A `CLAUDE.md`, `GEMINI.md`, rule, instruction file or skill folder without the marker is reported and left alone, and the command exits 1. Move its content into `AGENTS.md` and delete it, or pass `--force`: the old file is saved as `<path>.bak-agent-skills` first. * **Your own `.mcp.json` servers are kept.** `--force` leaves such a file alone; only `--force-mcp` replaces it, saving the old one as `.mcp.json.bak-agent-skills`. That backup may hold an `env` block with tokens, so delete it or ignore it before `git add`. * **Your own skills are never touched.** Only folders named like an agent-skills skill are managed. * **Everything stays inside the repository.** A link that points outside it is refused, reported and skipped; the command exits 1. * **`--check` and `--dry-run` write nothing.** `--check` exits 1 when a generated file is missing, differs or has no marker, and is the gate to use in CI. `--skills a,b` limits which skills are copied, and `--json` prints a machine-readable report. `agent-skills doctor` lists each of the seven agents as `configured` or `not configured` for the current repository, with the reason, for example `CLAUDE.md missing`. It reports; it does not change anything. The generated files do not yet include the guard hook of each agent or the subagent roles of `.claude/agents/`. ## Agents in Skribly Agent [Section titled “Agents in Skribly Agent”](#agents-in-skribly-agent) Skribly Agent runs 13 agents, more than agent-skills supports. Aider, Amp, Factory Droid, Qwen Code, Goose, Crush and Kimi CLI run in Skribly but have no skill target. See [Supported agents in Skribly Agent](/agent/agents/).

# Commits without AI trailers

> The three independent layers agent-skills uses so commits look like yours - the skills themselves, the Claude Code attribution setting and a commit-msg hook for any tool.

Commits should look like yours. agent-skills uses three independent layers, so one failing does not matter. ## 1. The skills [Section titled “1. The skills”](#1-the-skills) `commit` and `task` write messages in the project’s convention, from `.tasks/workflow.md` or detected from your own recent commits, and never add trailers: no `Co-Authored-By`, no “Generated with”, no agent links or emoji signatures. They commit only after you say OK, stage only the listed files, and never push, merge, rebase or force unless you ask in that conversation. ## 2. The Claude Code setting [Section titled “2. The Claude Code setting”](#2-the-claude-code-setting) 
```bash
agent-skills config attribution off                # ~/.claude/settings.json
agent-skills config attribution off --project .    # this project's .claude/settings.json
agent-skills config attribution status
agent-skills config attribution on                 # undo
```
 It sets `"attribution": { "commit": "", "pr": "" }`, which hides the commit trailer and the pull request footer, and the older `"includeCoAuthoredBy": false` for earlier Claude Code versions. Other keys are kept, a backup is written before the first change, and invalid JSON is never overwritten. ## 3. The git hook, for any tool [Section titled “3. The git hook, for any tool”](#3-the-git-hook-for-any-tool) 
```bash
cd ~/code/shop
agent-skills hooks install
agent-skills hooks status
agent-skills hooks uninstall
```
 The `commit-msg` hook removes: * `Co-authored-by:` trailers. All of them by default; to keep human co-authors, run `git config agent-skills.keepHumanCoauthors true`, and only AI ones are removed. * Footers such as “Generated with Claude Code”, “Generated by GitHub Copilot” or “Made with Cursor”. A “generated, made or created with” line is removed only when it names an AI tool, so “Generated with protoc” stays. It never touches anything else: the subject, the body, `Signed-off-by`, comment lines and everything below the scissors line of `git commit -v` stay byte for byte, line endings included. * Your existing `commit-msg` hook is kept and still runs after this one; uninstalling restores it. * In repositories that use husky, lefthook or another `core.hooksPath`, the installer does not take over that folder. It prints one line to add to your own hook: `node .git/hooks/agent-skills-commit-msg.cjs "$1"`. * The hook needs `node` on `PATH`; without it, the hook skips itself instead of blocking commits. * Hooks are per repository and are not committed. Install it in each clone. Skribly Agent has the same hook built in: **Code & git → Hook without AI trailers**. ## Checking old commits [Section titled “Checking old commits”](#checking-old-commits) 
```bash
git log --format='%h %s%n%b' | grep -inE 'co-authored-by|generated with' | head
```
 Rewriting published history is a team decision; agent-skills never does it.

# Install agent-skills

> Install agent-skills for one or all eight agents, at user or project scope, keep it updated and remove it cleanly.

## Requirements [Section titled “Requirements”](#requirements) * `git` and **Node.js 20 or newer** (`node --version`). No npm packages are installed: the CLI and every skill script use only Node’s standard library. * At least one supported agent: Claude Code, Codex CLI, Cursor, Gemini CLI, OpenCode, Windsurf, GitHub Copilot or Devin. ## Install in a minute [Section titled “Install in a minute”](#install-in-a-minute) 1. Clone the repository and put the command on your `PATH`: 
   ```bash
   git clone https://github.com/skribly/agent-skills.git ~/agent-skills
   cd ~/agent-skills
   npm link
   ```
 2. Install every skill for every agent, at user scope: 
   ```bash
   agent-skills install --target all
   ```
 3. Turn off Claude Code’s own attribution and check the result: 
   ```bash
   agent-skills config attribution off
   agent-skills doctor
   ```
 4. Restart your agent, or open a new chat, so it reads its skills folder again. Then try `/task 123` in Claude Code or `$task 123` in Codex. On Windows use the same commands in PowerShell with `$HOME\agent-skills`. Folder links are created as junctions, which need no administrator rights. Without `npm link`, run `node cli/agent-skills.mjs …` or `bin\agent-skills.cmd …`. ## User scope or project scope [Section titled “User scope or project scope”](#user-scope-or-project-scope) | | User scope (default) | Project scope | | -------- | ----------------------------------------- | --------------------------------------------------------- | | Command | `agent-skills install --target all` | `agent-skills install --target all --project ~/code/shop` | | Where | `~/.claude/skills`, `~/.agents/skills`, … | `<project>/.claude/skills`, `<project>/.agents/skills`, … | | How | Symlinks to the repository | Copies | | Updates | `git pull`, then `agent-skills sync` | `agent-skills sync` after `git pull` | | Good for | Your own machine, all projects | Sharing with a team through the project’s repository | A project-scope install also detects the project profile, `.skribly/project.json`; pass `--no-detect` to skip it. You can mix them: install everything at user scope and commit `task` and `commit` into a team project so colleagues get them too. Choose explicitly with `--scope user|project`, `--link` or `--copy`. ## Choose skills and agents [Section titled “Choose skills and agents”](#choose-skills-and-agents) 
```bash
agent-skills install --target claude,codex --skills task,commit,handoff,review,test-loop,token-saver
agent-skills list
```
 `--target` takes `claude`, `codex`, `cursor`, `gemini`, `opencode`, `windsurf`, `copilot`, `devin` or `all`. `--format rules` writes the classic formats for older agent versions; see [Supported agents](/skills/agents/). ## Recommended setup [Section titled “Recommended setup”](#recommended-setup) 
```bash
agent-skills config attribution off             # Claude Code: no Co-Authored-By trailer or PR footer
cd ~/code/shop && agent-skills hooks install    # per repository: strip AI trailers from any tool
```
 Then configure your tracker as in [Trackers](/skills/trackers/). ## Connect a tracker [Section titled “Connect a tracker”](#connect-a-tracker) 
```bash
agent-skills tasks check
agent-skills tasks list
agent-skills tasks fetch 482
```
 Credentials come from environment variables or `~/.config/agent-skills/credentials.env`, never from the repository. The first fetch writes `.tasks/<id>/TASK.md`, later fetches print only what changed, and `.tasks/` is excluded locally, so fetched tickets stay out of commits. ## Update and remove [Section titled “Update and remove”](#update-and-remove) 
```bash
cd ~/agent-skills && git pull && agent-skills sync      # refresh everything that was installed
agent-skills uninstall --target all                     # user scope
agent-skills uninstall --target all --project ~/code/shop
```
 Installs are recorded in `~/.config/agent-skills/installs.json` with a hash of each file. `uninstall` removes only what agent-skills installed, keeps files you edited unless you pass `--force`, and deletes folders it leaves empty. A file agent-skills did not write is never overwritten; with `--force` it is moved to `<path>.bak-agent-skills` first. ## CLI reference [Section titled “CLI reference”](#cli-reference) | Command | Purpose | | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | | `agent-skills list [--json]` | The catalogue | | `agent-skills install --target <agents\|all> [--scope user\|project] [--project <dir>] [--skills a,b] [--link\|--copy] [--format skills\|rules] [--dry-run] [--force]` | Install | | `agent-skills uninstall --target … [--scope] [--project] [--skills]` | Remove only what was installed | | `agent-skills sync` | Re-apply every recorded install after `git pull` | | `agent-skills project [--project <dir>] [--dry-run] [--json]` | Detect the project into `.skribly/project.json`, keeping values set by hand | | `agent-skills agent-files [--project <dir>] [--check] [--force] [--force-mcp] [--skills a,b\|all] [--dry-run] [--json]` | Generate the per-agent files of a repository from its `AGENTS.md`; # Trackers

> Connect agent-skills to Redmine, Jira, GitHub, GitLab, Linear or Skribly Tracker, and use the tasks commands that the task skill runs.

The `task` skill fetches issues with a script (`agent-skills tasks`), so the model spends no tokens on HTTP, pagination or re-reading. The first fetch writes `.tasks/<id>/TASK.md`; later fetches print only what changed: new comments, status, a changed description, new attachments. ## Credentials [Section titled “Credentials”](#credentials) Put them in environment variables or in `~/.config/agent-skills/credentials.env` (Windows: `%USERPROFILE%\.config\agent-skills\credentials.env`). Environment variables win over the file. Start from the template in the repository: 
```bash
mkdir -p ~/.config/agent-skills
cp templates/credentials.env.example ~/.config/agent-skills/credentials.env
chmod 600 ~/.config/agent-skills/credentials.env     # doctor warns if others can read it
agent-skills tasks check                             # who am I, per configured tracker
```
 Never put tokens in a repository, in `.tasks/` or in a chat. Point at another file with `AGENT_SKILLS_CREDENTIALS`. Inside [Skribly Agent](/agent/features/#tasks-and-trackers), sessions receive these variables from the app, so no file is needed. ## Skribly Tracker [Section titled “Skribly Tracker”](#skribly-tracker) 
```bash
SKRIBLY_TRACKER_URL=http://localhost:8100   # base URL of the instance
SKRIBLY_TRACKER_TOKEN=...                   # Profile -> API tokens
```
 Ids: `ABC-12` or an `/issues/ABC-12` URL on the `SKRIBLY_TRACKER_URL` host. The client uses [REST API v1](/tracker/rest-api/); descriptions and comments are already Markdown, and attachments are downloaded with the same token. “My open tasks” is `assignee=me&status=open&sort=-updated`. Older setups keep working: `skryba` is an alias of the `skribly` tracker id, and `SKRYBA_TRACKER_URL` and `SKRYBA_TRACKER_TOKEN` are read when the matching `SKRIBLY_TRACKER_*` variable is not set. ## Redmine [Section titled “Redmine”](#redmine) 
```bash
REDMINE_URL=https://redmine.example.com
REDMINE_API_KEY=...        # My account -> API access key (an admin must enable the REST API)
```
 Ids: `123`, `#123` or an `/issues/123` URL. Comments are journal notes. ## Jira Cloud [Section titled “Jira Cloud”](#jira-cloud) 
```bash
JIRA_URL=https://your-team.atlassian.net
JIRA_EMAIL=you@example.com
JIRA_API_TOKEN=...         # id.atlassian.com -> Security -> API tokens
```
 ## Jira Server / Data Center [Section titled “Jira Server / Data Center”](#jira-server--data-center) 
```bash
JIRA_URL=https://jira.example.com
JIRA_PAT=...               # Profile -> Personal Access Tokens
```
 Ids: `ABC-123` or a `/browse/ABC-123` URL. Wiki markup is converted to Markdown. ## GitHub [Section titled “GitHub”](#github) 
```bash
GITHUB_TOKEN=...           # fine-grained token: Issues read (write only to post comments)
GITHUB_API_URL=https://github.example.com/api/v3   # GitHub Enterprise Server only
```
 Without a token, a signed-in GitHub CLI (`gh auth login`) is used, and public issues work anonymously at 60 requests an hour. Ids: `7` (the repository of the `origin` remote), `owner/repo#7` or an issue URL. ## GitLab [Section titled “GitLab”](#gitlab) 
```bash
GITLAB_TOKEN=...           # read_api (api to post comments)
GITLAB_URL=https://gitlab.example.com   # default https://gitlab.com
```
 Ids: `7`, `group/sub/project#7` or a `/-/issues/7` URL. System notes are skipped. ## Linear [Section titled “Linear”](#linear) 
```bash
LINEAR_API_KEY=lin_api_...  # Settings -> Security & access -> Personal API keys
```
 Ids: `ENG-12` or a `linear.app/.../issue/ENG-12/...` URL. ## Which tracker does an id mean? [Section titled “Which tracker does an id mean?”](#which-tracker-does-an-id-mean) In order: `--tracker`, the `Tracker:` line in `.tasks/workflow.md`, `AGENT_SKILLS_TRACKER`, then whichever tracker is configured. A configured Redmine wins for plain numbers; GitHub or GitLab when the `origin` remote points there. `ABC-12` can be Jira, Linear or Skribly Tracker: the same three settings decide, otherwise the only configured one is used, and with several you are asked. A task fetched once remembers its tracker. ## Commands [Section titled “Commands”](#commands) 
```bash
agent-skills tasks fetch 123                 # TASK.md; on re-fetch only the changes
agent-skills tasks attachments 123 [name]    # images by default, --all for every file
agent-skills tasks list                      # my open issues in every configured tracker (--json)
agent-skills tasks list --local              # tasks in .tasks/ with status, branch and next step
agent-skills tasks comment-draft 123         # create or show .tasks/123/COMMENT.md
agent-skills tasks comment-draft 123 --post --yes    # publish, only after your explicit OK
agent-skills tasks detect                    # git facts used to write .tasks/workflow.md
agent-skills tasks check                     # configuration and token test
```
 ## Safety [Section titled “Safety”](#safety) * Read-only by default. Writing needs `--post --yes`, and the same text is never posted twice. * Tokens are sent only to the tracker’s own host. Redirects to another host, such as a CDN serving an attachment, are followed without credentials. * Behind a corporate proxy with TLS errors, point `NODE_EXTRA_CA_CERTS` at the proxy’s CA certificate.

# Troubleshooting agent-skills

> Fixes for common agent-skills problems - agents that do not see skills, install conflicts, Windows links, tracker errors, the commit hook and optional tools.

## The agent does not see the skills [Section titled “The agent does not see the skills”](#the-agent-does-not-see-the-skills) * Run `agent-skills doctor`: it shows which agents were detected and where skills are installed. * Restart the agent or start a new chat; most agents scan skill folders at startup. * Check the location for your agent in [Supported agents](/skills/agents/). Older versions may need `--format rules`. * Codex lists a skill twice: old copies sit in the deprecated `~/.codex/skills`. `doctor` warns about them; remove them. * Cursor, OpenCode or Copilot list a skill twice in a project: they also read `.claude/skills`. Install Claude at user scope and the others at project scope, or the reverse. ## `agent-skills: command not found` [Section titled “agent-skills: command not found”](#agent-skills-command-not-found) Run `npm link` in the repository, call `node ~/agent-skills/cli/agent-skills.mjs`, or link `bin/agent-skills` into a folder on `PATH` (`ln -s ~/agent-skills/bin/agent-skills ~/.local/bin/`). On Windows use `bin\agent-skills.cmd`. ## “exists and was not installed by agent-skills” [Section titled ““exists and was not installed by agent-skills””](#exists-and-was-not-installed-by-agent-skills) A file or folder with the same name was already there, so it was left alone. Compare it, then rerun with `--force`; the old one is moved to `<path>.bak-agent-skills`. ## `sync` or `uninstall` skips a copy I edited [Section titled “sync or uninstall skips a copy I edited”](#sync-or-uninstall-skips-a-copy-i-edited) On purpose: hand-edited copies are never overwritten or deleted. Keep your edit, or use `--force` to replace or remove it. ## Links on Windows [Section titled “Links on Windows”](#links-on-windows) User-scope installs create folder junctions, which need no administrator rights or developer mode. If a junction cannot be created, for example on some network drives, install with `--copy` and run `agent-skills sync` after updates. ## WSL and Windows at the same time [Section titled “WSL and Windows at the same time”](#wsl-and-windows-at-the-same-time) Each environment has its own home folder and agents. Install in both, from one clone if you like, running `agent-skills install` inside each environment. ## Tracker problems [Section titled “Tracker problems”](#tracker-problems) * `access denied (HTTP 401/403)`: a wrong or expired token, or a missing scope. `agent-skills tasks check` tests every tracker. * `cannot resolve` or `no connection`: VPN or URL. `TLS problem`: set `NODE_EXTRA_CA_CERTS` to your company’s CA certificate. * `ENG-12 could be Jira or Linear` (or Skribly Tracker): add `Tracker: jira` (or `linear`, `skribly`) to `.tasks/workflow.md`, set `AGENT_SKILLS_TRACKER`, or pass `--tracker`. * GitHub without a token: public issues work at 60 requests an hour; private ones need `GITHUB_TOKEN` or `gh auth login`. ## PageSpeed Insights says HTTP 429 [Section titled “PageSpeed Insights says HTTP 429”](#pagespeed-insights-says-http-429) The keyless quota is shared and often used up. Create an API key for the PageSpeed Insights API and set `PSI_API_KEY`, or measure locally with `--local`, which needs Chrome. ## Playwright or axe-core is missing [Section titled “Playwright or axe-core is missing”](#playwright-or-axe-core-is-missing) `browser-check`, `wcag-audit` and `e2e-tests` look for Playwright in the project, then globally. Install it only if you want it: `npm i -D playwright axe-core && npx playwright install chromium`. Without it the skills fall back to manual checklists and say so. ## The commit-msg hook did not run [Section titled “The commit-msg hook did not run”](#the-commit-msg-hook-did-not-run) * Run `agent-skills hooks status` in that repository. Hooks are per repository. * husky, lefthook and similar tools set `core.hooksPath`; add the printed line to their `commit-msg` hook. * `node` must be on `PATH` for git. GUI clients sometimes have a minimal `PATH`. ## Does it send my code anywhere? [Section titled “Does it send my code anywhere?”](#does-it-send-my-code-anywhere) No. The CLI talks only to your tracker (when you fetch, or explicitly post), to OSV.dev or PageSpeed Insights when you run those audits, and to package registries through your own package manager. Nothing else is collected or uploaded. ## How do I use it in a team? [Section titled “How do I use it in a team?”](#how-do-i-use-it-in-a-team) Install at project scope (`--project .`) and commit `.claude/skills` and `.agents/skills`, so everyone gets the same skills. `.tasks/` stays personal. Put shared conventions (base branch, commit pattern, check commands) in `AGENTS.md`, and each developer’s `.tasks/workflow.md` is proposed from them. Each developer installs the commit hook in their own clone.
